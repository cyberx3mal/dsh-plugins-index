# dsh-plugins-index

Подборка плагинов DSH (формат 1). Пять своих плагинов ставятся из Git-коммитов, два плагина
сообщества (`dsh-better-sidebar`, `dsh-widgets`) — из npm. Состав:

```
index.json         индекс: 7 плагинов
icons/*.svg        иконки, лежат рядом с индексом (ссылки относительные)
update-index.mjs   пересобирает Git-записи из локальных чек-аутов
```

Свои плагины (Git, версия = пин на коммит):

| Плагин | Источник |
|---|---|
| `dsh-plugin-project-sounds` | `cyberx3mal/DSH-Sounds` |
| `@local/docker-sidebar` | `cyberx3mal/DSH-Docker` |
| `@local/sidebar-widget-order` | `cyberx3mal/DSH-sidebar-widget-order` |
| `@local/projects-board` | `cyberx3mal/DSH-Projects` |
| `@local/music-board` | `cyberx3mal/DSH-Music` |

Сторонние (npm, MIT, с меткой `third-party`):

| Плагин | Версия | Автор |
|---|---|---|
| `dsh-better-sidebar` | 0.32.1 | omdsh-dev |
| `dsh-widgets` | 1.9.2 | Physicolor |

npm-записи workflow обновляет сам: читает `dist-tags.latest` из реестра и добавляет версию
с временем публикации. Локальный `update-index.mjs` npm-записи не трогает — у него нет сети.

## Подключить в DSH

Индекс уже опубликован:

```
https://raw.githubusercontent.com/cyberx3mal/dsh-plugins-index/main/index.json
```

В DSH: **Plugins → Discover → «Добавить источник индекса»** → вставить этот URL → «Добавить».
Этот адрес отдаёт `text/plain` — DSH тип содержимого не проверяет; кеш edge около 5 минут.

## Обновление плагинов

DSH обновляет на месте только плагины, установленные из npm-реестра: у них на странице плагина
есть блок **«Версии»** и кнопка **«Обновить»** (или «Обновление до X» в шапке страницы).

Плагины из Git (все пять своих) так не обновляются — блока «Версии» у них нет, а кнопка
**«Доступно обновление»** в Discover только показывает статус и ведёт в «Установленные».
Чтобы получить свежую версию:

1. **Plugins → Установленные → плагин → «Удалить»**;
2. **Plugins → Discover → плагин → «Установить»** — индекс к этому моменту уже содержит
   свежий коммит (workflow обновляет его каждый час; кнопка «Обновить» на вкладке Discover
   перезапрашивает индекс, не дожидаясь кеша).

Или из терминала: `dsh plugin --profile desktop add github:<owner>/<repo>#<commit>`, затем
перезапустить DSH.

## Сайт

`index.html` — статическая страница подборки: читает `index.json` рядом с собой, показывает карточки
с иконками, поиск, категории, сортировку и кнопку «Скопировать установку».

```
https://cyberx3mal.github.io/dsh-plugins-index/
```

Публикуется через GitHub Pages (Settings → Pages → Deploy from a branch → `main` / `/ (root)`).
Страница не требует сборки и не дублирует данные: всё берётся из `index.json`.

## GitHub Pages (по желанию, для красивого адреса)

Settings → Pages → Source: **Deploy from a branch** → `main` / `/ (root)`. Через минуту
`https://cyberx3mal.github.io/dsh-plugins-index/index.json` отдаёт тот же файл с `application/json`.
В Discover можно оставить любой из двух адресов.

Редиректы запрещены: используйте только финальные адреса. Ссылки вида
`https://github.com/cyberx3mal/dsh-plugins-index/raw/main/index.json` (302) и `.../blob/...` (HTML) не подойдут.

## Автообновление (GitHub Actions)

`.github/workflows/update-index.yml` запускается каждый час (`17 * * * *` UTC) и вручную:
Actions → **Update index** → **Run workflow**. Что делает:

1. `scripts/update-index.mjs` для каждой Git-записи берёт из её `source.url` владельца и репозиторий,
   читает default-branch head через GitHub API, `package.json` этого коммита и дату коммита;
2. новая версия → добавляется в начало `versions` (старые остаются, хранится до 20);
3. версия уже есть, но пин стоит на другом коммите → скрипт читает `package.json` того коммита:
   если там другая версия, запись перепинивается на head (так лечится запись, попавшая в индекс
   до пуша бампа версии); если версия та же — в логе `::warning::` «поднимите version», индекс
   не меняется;
4. npm-записи обновляются из реестра: `dist-tags.latest` добавляется в начало `versions` вместе
   со временем публикации, если такой версии ещё нет;
5. `icons/*.svg` обновляются из репозитория того же коммита;
6. `scripts/validate-index.mjs` проверяет файл валидатором DSH (`@deepseek-ai/dsh-plugin-market-index@0.2.2-rc.2`,
   ставится в CI через npm);
7. коммит и пуш только если что-то изменилось, от `github-actions[bot]`.

После пуша изменения доезжают до пользователей за ~10–20 минут (кеш raw/DSH).

Локальный вариант — `update-index.mjs` в корне: он делает то же самое для Git-записей, но по
локальным чек-аутам из `checkouts`, без сети и без GitHub API. Версию он берёт из `HEAD`, поэтому
незакоммиченный бамп в рабочей копии в индекс не попадёт.

## После релиза плагина

Обычно ничего делать не нужно: достаточно поднять `version` в `package.json`, закоммитить и
запушить — ближайший прогон workflow (или ручной **Run workflow**) обновит `index.json` сам.

Ручной путь (если не ждать cron):

1. Поднимите `version` в `package.json` плагина, закоммитьте и запушьте.
2. Запустите `node update-index.mjs` — скрипт возьмёт версию и коммит из `HEAD`, время коммита
   и `icon.svg` из локальных папок, перечисленных в `checkouts`, и перепишет `index.json`.
3. Закоммитьте и запушьте `index.json`.

DSH кеширует индекс 10 минут; кнопка **«Обновить»** в Discover запрашивает заново.
Pages/Fastly после деплоя тоже отдаёт новое содержимое не мгновенно (до ~10 минут).

## Ограничения

- Имена `@local/*` и `"private": true` для установки из Git допустимы (private влияет только на
  публикацию в npm), но с такими именами плагины нельзя опубликовать в реестр. На машине, где эти же
  имена уже стоят через `link:` (dev-копии), установка из индекса **заменит** их пинами коммитов.
- Версия в индексе должна совпадать с `version` в `package.json` того коммита. Без поднятия версии
  новый коммит не отобразится как обновление — карточка останется на прежней версии.
- Индекс читается Host-процессом без авторизации и без следования редиректам: репозиторий и Pages
  должны быть публичными.
- `engines.dsh` в манифестах нет, поэтому версии считаются совместимыми с любой DSH; при установке
  DSH дополнительно проверяет `@deepseek-ai/dsh*` peer-зависимости (здесь их нет).

## Проверка перед пушем

```powershell
node -e "JSON.parse(require('fs').readFileSync('index.json','utf8')); console.log('json ok')"
```

Полноценная проверка формата — просто добавьте источник в Discover: ошибка покажет JSON-путь
нарушенного правила под источником в «Управление источниками индексов…».
